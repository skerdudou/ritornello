# Oüi FM — what's playing

Shows the artist, the title and the cover art for **Oüi FM and its twenty-odd
webradios** — Classic Rock, Rock Indé, Alternatif, Blues'n'Rock, the decade
stations, and the rest.

It is a `metadata` plugin for [Ritornello](../../README.md); see
[docs/plugins.md](../../docs/plugins.md) for what that means.

## Why you want it

The stream itself is no help. Of five Oüi FM streams measured, only one carried
anything usable in its broadcast metadata — and that one was a foreign
webradio. The main station announces a placeholder, word for word:

> **Now Playing info goes here**

So without this plugin you get a filler string, or nothing, depending on the
webradio. Oüi FM does publish what is on air though, on a feed of its own, with
the artist and the title already separated and a cover image alongside — and
often a link to the track on Deezer or Apple Music, which the plugin passes
along too.

## Installing it

**There is nothing to configure.** The webradio list is built into the binary.
Deploy as usual and any Oüi FM stream already set up on the device starts
showing titles.

An optional `/etc/ritornello/ouifm-metas.toml` (see
[the example](../../deploy/ouifm-metas.example.toml)) lets you correct a
webradio or add one without rebuilding, should Oüi FM ever change a stream
address.

## How it works, in short

Rather than asking again and again, the plugin opens one connection to Oüi FM's
feed and keeps it open: the station pushes each new track as it starts. That is
why the title appears promptly without the device polling anyone, and why
switching webradio is the only thing that reopens a connection.

A detail worth knowing, because it explains the table shipped with the plugin:
the identifier in a stream's URL is **not** the one the metadata feed answers
to. Each webradio therefore has two, and the plugin's table pairs them —
checked by hand, since asking the feed with the stream's own identifier returns
an empty frame rather than an error.

Covers are requested at the size the host actually stores, 600 px. Larger
widths do answer, but with an upscale of that same image: more bytes, no more
detail.

## Maintaining it

Regenerate the table and the list above from Oüi FM's own player page:

    node crates/ritornello-plugin-ouifm-metas/scripts/fetch-webradios.mjs

Both files are written from the same run, so they cannot disagree. With
`--verifier` the script writes nothing and exits nonzero if either has drifted.

There is no public API for this list — it lives in a JavaScript variable on the
player page, which is why the table is embedded in the binary rather than read
at startup: a device that boots unattended must not depend on a third party's
page to recognize its stations, and such a failure would be silent.

The reasoning behind each rule — how a frame is parsed, why the cover host is
compared as an authority rather than a prefix, how the historical mounts were
cross-checked — lives in the comments of `src/stream.rs` and `src/table.rs`,
next to the code it explains.

One thing has no other home: the feed is **private and undocumented**. It may
change, start requiring authentication, or disappear without notice. Its
failure is silent on screen, never delays playback, and reconnection backs off
progressively rather than hammering a third party's server.
