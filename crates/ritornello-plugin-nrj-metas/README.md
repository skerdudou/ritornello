# NRJ group — what's playing

Shows the artist, the title and the cover art for the webradios of the NRJ
group: **NRJ, Nostalgie, Chérie FM and Rire & Chansons** — over 350 stations
between them.

It is a `metadata` plugin for [Ritornello](../../README.md); see
[docs/plugins.md](../../docs/plugins.md) for what that means.

## Why you want it

These stations do announce something in their stream, but it is an internal
scheduling code rather than a title. Without this plugin, a Rire & Chansons
listener sees:

> **DD25-19 - DD25-19**

With it:

> **TOM VILLA** — On se juge

The code even looks like an ordinary `Artist - Title` pair, so nothing
downstream can tell it is meaningless — it just gets shown. That is what this
plugin replaces, by reading each brand's own on-air feed instead, where the
artist and the title come already separated, with a cover image alongside.

## Installing it

**There is nothing to configure.** The station list is built into the binary.
Deploy as usual and any NRJ-group station already set up on the device starts
showing titles.

One case needs a hand: **on a device already in service**, `deploy.sh` appends
the new plugin at the end of `/etc/ritornello/plugins.toml`, which puts it
*after* `musicbrainz`. Move the `nrj-metas` block above `musicbrainz` by hand —
otherwise MusicBrainz's guess wins over the station's own answer. A fresh
install already has the right order.

An optional `/etc/ritornello/nrj-metas.toml` (see
[the example](../../deploy/nrj-metas.example.toml)) lets you correct a station
or add one without rebuilding, should the group ever change a stream address.

## How it works, in short

Each brand's website publishes what is on air right now. The plugin asks the
site that owns your station — and only that one, since a brand's site answers
for its own stations alone.

The interesting part is *when* it asks. The on-air feed lags behind the actual
stream by up to a minute, so polling it on a timer would mostly report the
previous song. The stream's own scheduling code, useless as a title, turns out
to change **before** the feed does — so the plugin uses it as its cue: the code
says *when* something changed, the feed says *what* it is.

Two things it deliberately does not show. When a station announces its own name
instead of a track — which happens, and on some stations more often than not —
you get the station name and its logo rather than a wrong title. And when the
announced image is the station's generic wallpaper rather than the track's own
artwork, the plugin stays quiet about the cover, so MusicBrainz can look for a
real one.

## Maintaining it

Regenerate the table and the list above from the brands' own endpoints:

    node crates/ritornello-plugin-nrj-metas/scripts/fetch-stations.mjs

Both files are written from the same fetch, so they cannot disagree. With
`--verifier` the script writes nothing and exits nonzero if either has drifted
from the sources.

The reasoning behind each rule — the measurements, the timings, why the request
rhythm is what it is — lives in the comments of `src/live.rs` and
`src/main.rs`, next to the code it explains.

One thing has no such home, so it is recorded here. `musicbrainz`, which runs
after this plugin, also probes a station's raw stream string to learn whether
it can be split into an artist and a title. On these stations that string is
the scheduling code, so its guess never validates against a real recording, and
its own anchoring rule stops it reprobing after five attempts. The whole
interaction is therefore bounded and harmless, with or without this plugin
installed — **no special case was added for it**, and none is needed.
