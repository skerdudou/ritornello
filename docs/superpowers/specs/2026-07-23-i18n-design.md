# ritornello — Internationalisation (i18n)

Rendre l'interface multilingue (anglais de base + français, extensible) : texte
d'affichage (console/OLED), messages de validation, et pages web — le tout via
un catalogue Rust partagé, avec des packs de langue **décentralisés par plugin**
pour rester cohérent avec l'écosystème à plugins.

Date : 2026-07-23 — Statut : validé

## Contexte

Aujourd'hui tout le texte utilisateur de ritornello est du français codé en dur,
dispersé dans les binaires : le cœur (`VEILLE` sur l'écran de veille), le plugin
cd (`pas de disque`, `CD audio`, `CD piste {n}`), le plugin radio (`présélection
vide` et ses messages de validation `présélection hors bornes` / `en double`),
et les pages web (page de statut du cœur + page d'admin radio, servies depuis la
livraison « serveur web unique » sous l'origine unique `:8080`).

Cette livraison est la 2e des deux specs séquentielles décidées ; elle s'appuie
sur l'origine HTTP unique déjà livrée (spec `2026-07-23-serveur-web-unique-design.md`).

Contrainte d'écosystème : comme pour les genres de plugin, on ne peut pas
connaître à l'avance la liste des plugins. Un fichier de langue central est donc
exclu — chaque composant (cœur ou plugin) possède ses propres ressources de
langue, indépendamment des autres.

## Décisions de cadrage

| Sujet | Décision |
|---|---|
| Portée | **Une seule spec complète** : fondation + texte Rust (affichage + validation) + pages web. |
| Langue de base | **Anglais**, embarqué dans chaque binaire (`include_str!`), filet de dernier recours toujours résolu. |
| Packs additionnels | Fichiers TOML externes, **décentralisés par composant** : `<root>/<composant>/<lang>.toml`. |
| Vocabulaire commun | Catalogue `common` (play/pause/stop/error…) embarqué dans le crate partagé `ritornello-i18n`, réutilisable par tous sans duplication ni appel IPC. |
| Résolution | Par clé : `own` du composant → `common` → (anglais embarqué en dernier recours dans chaque couche). Traduction manquante = repli anglais **par clé**. |
| Traduction web | **Rendu serveur** via le même catalogue Rust (pas d'i18n en JS, pas de catalogue exposé en JSON). |
| Propagation | Langue courante poussée aux plugins Source via `SourceReq::SetLocale(String)` sur le canal IPC existant. |
| Sélecteur | Sur la page de statut du cœur (`GET`/`PUT /api/locale`), calque de `/api/audio-output`. |
| Persistance | `PersistedState.locale: Option<String>` (`None` = anglais de base). |
| Hors périmètre | Messages de log/erreur internes (anyhow/tracing, destinés au dev) ; détection auto de langue ; pluriels/genre. |

## Le crate `ritornello-i18n`

Nouveau crate partagé (dépendance du cœur ET des plugins qui produisent du texte).

- `Catalog` — deux sous-couches **indépendantes** (évite toute collision de clés
  entre le vocabulaire propre d'un composant et le vocabulaire commun) :
  - `own` : map issue de l'anglais embarqué du composant (`en.toml` fourni par le
    binaire via `include_str!`), surchargée par le pack externe
    `<root>/<composant>/<lang>.toml` s'il existe.
  - `common` : map issue de l'anglais embarqué **dans `ritornello-i18n`**,
    surchargée par `<root>/common/<lang>.toml` s'il existe.
- `Catalog::load(component: &str, locale: &str, root: &Path, own_en: &str) -> Catalog` :
  - part de l'anglais embarqué (`own_en` pour `own`, la constante `common` du crate
    pour `common`) ;
  - superpose le pack externe correspondant s'il est présent et valide ;
  - un fichier absent est ignoré **silencieusement** (cas normal : un pack de
    langue manquant pour un composant/une langue est attendu) ; un TOML
    **invalide** est ignoré avec un `warn` loggé ; dans les deux cas on garde
    l'anglais — jamais de panique.
- `Catalog::get(&self, key: &str) -> &str` : `own.get(key)`, sinon `common.get(key)`,
  sinon `key` (filet ; ne se produit pas pour une clé connue puisque l'anglais
  embarqué la couvre).
- Fonction de parsing du TOML séparée de l'accès disque (fonction pure testable,
  comme `audio_output::parse_device_list` déjà dans le projet).

Format des fichiers : TOML plat, `clé = "valeur"`. Clés en `snake_case`
namespacées par intention (ex. `standby`, `no_disc`, `cd_audio`, `empty_preset`
côté composant ; `play`, `pause`, `error` côté common).

## Disposition des fichiers de langue

```
/etc/ritornello/locales/
  common/fr.toml        ← vocabulaire commun (fourni par le projet)
  core/fr.toml          ← texte propre au cœur + chrome de la page de statut
  radio/fr.toml         ← texte du plugin radio + page d'admin radio
  cd/fr.toml            ← texte du plugin cd
  <plugin-tiers>/fr.toml ← un plugin tiers, jamais connu du cœur
```

- Racine configurable par `RITORNELLO_LOCALES` (défaut `/etc/ritornello/locales`),
  lue indépendamment par chaque processus.
- Chaque binaire connaît son **nom de composant** en dur (`core`, `radio`, `cd`)
  et embarque son anglais de base dans `crates/<crate>/src/locales/en.toml`, chargé
  via `include_str!("locales/en.toml")` (chemin relatif au module qui construit le
  catalogue). Le crate `ritornello-i18n` embarque de même son `common` anglais dans
  `crates/ritornello-i18n/src/locales/common_en.toml`.
- Le projet fournit les packs français initiaux (`common/fr.toml`, `core/fr.toml`,
  `radio/fr.toml`, `cd/fr.toml`) dans `deploy/locales/`, copiés vers
  `/etc/ritornello/locales/` par `deploy/deploy.sh`.

## Choix, persistance et propagation de la langue

- `PersistedState.locale: Option<String>` (`#[serde(default)]`). `None` = anglais
  de base. Appliqué au démarrage et à chaque changement, comme `audio_device`.
- Page de statut du cœur :
  - `GET /api/locale` → `{ locales: Vec<String>, current: Option<String> }`.
  - `PUT /api/locale { locale: String }` → persiste, reconstruit le catalogue du
    cœur, et pousse `SetLocale(locale)` à chaque plugin Source connecté.
  - Un petit `<select>` + bouton sur `/status`, calqué sur le sélecteur de sortie
    audio existant.
- **Liste des langues** proposées = celles que le **cœur** possède : `en`
  (toujours, embarqué) + tout `<root>/core/*.toml` présent (ex. `fr`). Découverte
  par lecture du répertoire `<root>/core/` (fonction pure de parsing des noms de
  fichiers séparée de l'accès disque, testable).
- **Propagation** : nouvelle variante `SourceReq::SetLocale(String)` (le canal
  Source est déjà requête/réponse cœur→plugin). Le plugin Source stocke la langue
  courante (ex. `Arc<RwLock<String>>` ou champ interne) et reconstruit son
  `Catalog` ; ses `View` suivantes sont produites dans la nouvelle langue. La
  réponse à `SetLocale` est un simple `SourceAction::Noop` sans vue.
  - Console (Display) et mce (Input) n'ont aucun texte propre → non concernés.
  - La page d'admin de radio lit la **même** langue courante (radio est un seul
    processus ; l'état de langue posé par `SetLocale` sur la moitié Source est
    partagé avec la moitié Admin via `Arc<RwLock<…>>`).
  - Limite assumée : un futur plugin **non-Source** produisant du texte devrait
    étendre ce mécanisme (YAGNI aujourd'hui — seuls radio et cd produisent du
    texte, tous deux Source).
- Au démarrage, le cœur applique `persisted.locale` à lui-même et l'envoie via
  `SetLocale` à chaque plugin Source juste après la connexion (avant `resume()`,
  au même endroit conceptuel que `set_volume`/`set_audio_device`).

## Ce qui est traduit

- **Cœur (affichage)** : `standby_view()` `VEILLE` → `catalog.get("standby")`.
- **Cœur (page de statut, rendu serveur)** : titre, en-têtes de table
  (`Plugin`/`Genre`/`État`/`Admin`), `connecté`/`indisponible`, `Source active`,
  `Sortie audio`, `Changer`, `Dernières erreurs`, libellés du futur sélecteur de
  langue — tous via `catalog.get(clé)` inline dans la construction du HTML.
- **Plugin cd (affichage)** : `pas de disque` → `no_disc`, `CD audio` →
  `cd_audio`, `CD piste {n}` / `CD {n}/{total}` → clés avec interpolation
  (format appliqué après lookup).
- **Plugin radio (affichage)** : `présélection vide` → `empty_preset`.
- **Plugin radio (validation)** : `présélection {} hors bornes 1-9 ({})` et
  `présélection {} en double` → clés ; le message d'erreur remonté en `422` sur
  la page d'admin est donc traduit.
- **Plugin radio (page d'admin, rendu serveur)** : `index.html` passe de HTML
  statique à un gabarit avec jetons `{{clé}}` ; `AdminPlugin::page()` remplace
  chaque jeton par `catalog.get(clé)` selon la langue courante. **Conséquence
  d'interface** : `AdminPlugin::page()` passe de `-> &'static str` à `-> String`.

Les préfixes purement symboliques sans mot traduisible (ex. `RADIO  P{n}`) restent
tels quels.

## Interpolation

Les chaînes à variables gardent des marqueurs de format dans la valeur traduite
(ex. `empty_preset` n'a pas de variable ; `cd_track = "CD piste {n}"` en anglais
`"CD track {n}"`). Le composant fait `catalog.get(key)` puis applique le format
avec un simple `str::replace("{n}", &n.to_string())` (pas de moteur de template —
une ou deux variables par chaîne au plus). Cette règle est documentée dans le
crate `ritornello-i18n`.

## Erreurs / dégradation

Best-effort de bout en bout, cohérent avec la tolérance déjà en place :
- pack absent → anglais embarqué, **silencieusement** (cas normal, pas de log) ;
- clé manquante → anglais, puis la clé elle-même ;
- TOML illisible → `warn` loggé, traité comme absent (on garde l'anglais) ;
- langue inconnue reçue par `SetLocale` → le plugin charge ce qu'il trouve, sinon
  reste en anglais (aucune erreur fatale).
La dégradation est **par clé et par composant** : un plugin sans pack `fr` reste
en anglais pendant que le reste du système est en français.

## Tests

- `ritornello-i18n` : superposition de résolution (`own` > `common`, externe >
  embarqué, clé manquante → anglais → clé) sur des TOML en mémoire ; parsing pur
  séparé de l'accès disque.
- Cœur : `standby_view()` rend la clé traduite avec un faux catalogue `fr` ;
  `GET`/`PUT /api/locale` (liste + sélection) ; découverte des langues depuis un
  répertoire `core/` simulé ; rendu de la page de statut dans une langue donnée
  (le HTML contient la traduction, pas l'anglais) ; roundtrip JSON de
  `SourceReq::SetLocale`.
- Plugin cd / radio : la `View` (et, pour radio, le message de validation) utilise
  le catalogue — test avec un faux pack `fr` où la clé rend une valeur distincte.
- Plugin radio : `page()` substitue les jetons `{{clé}}` par les valeurs du
  catalogue de la langue courante.

## Hors périmètre

- Messages de log et d'erreur internes (`anyhow`/`tracing`) : destinés au
  développeur, pas à l'utilisateur final — laissés en français/anglais tels quels.
- Détection automatique de la langue (Accept-Language, locale système).
- Pluriels, genre, formatage de dates/nombres localisé : les clés simples avec
  interpolation basique suffisent au vocabulaire de ritornello.
- Traduction de la documentation (`README.md`, specs) : reste en français.
